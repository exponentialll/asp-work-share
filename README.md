# 💊 ASP 화이팅! (공동 업무 공유 앱)

지수, 다경 두 분이 같은 웹페이지 주소에 접속해서 실시간으로 같은 업무 목록을 보고 함께 기록·수정할 수 있는 앱입니다.
Notion의 "💊 ASP 업무 리스트" 데이터베이스 포맷(대분류/소분류/업무/날짜/텍스트/진행도/URL/담당자)을 기반으로 만들었고,
업무 리스트 외에도 공지사항, 캘린더, 개별 업무리스트, 회의, 아이디어, 소통일지, 업무매뉴얼, 자료실까지 한 공간에 모아뒀습니다.

데이터는 브라우저가 아니라 **Firebase(Firestore)** 라는 무료 클라우드에 저장되기 때문에, 두 분이 각자 컴퓨터에서
접속해도 같은 데이터를 실시간으로 보고 수정할 수 있습니다. 화면은 **GitHub Pages**로 무료 호스팅합니다.

처음 설정에 약 15~20분 정도 걸리고, 한 번만 해두면 이후에는 그냥 URL로 접속해서 쓰시면 됩니다.

---

## 1단계. Firebase 프로젝트 만들기 (무료)

1. https://console.firebase.google.com/ 접속 → 구글 계정으로 로그인
2. **"프로젝트 추가"** 클릭 → 프로젝트 이름 입력 (예: `asp-work-share`) → 계속
3. Google Analytics는 **꺼도 됩니다** (필요 없음) → 프로젝트 만들기
4. 왼쪽 메뉴에서 **빌드 → Firestore Database** 클릭 → **"데이터베이스 만들기"**
   - 위치는 `asia-northeast3 (서울)` 선택 권장
   - 보안 규칙은 우선 **"테스트 모드로 시작"** 선택 (아래 5단계에서 규칙을 다시 손봐드릴게요)
5. 왼쪽 위 톱니바퀴 ⚙️ → **프로젝트 설정** → 아래로 스크롤해서 **"내 앱"** → 웹 아이콘(`</>`) 클릭
6. 앱 닉네임 아무거나 입력 (예: `asp-web`) → 앱 등록
7. 화면에 나오는 `firebaseConfig` 객체의 값들을 복사해두세요. 예시:
   ```js
   const firebaseConfig = {
     apiKey: "AIza...",
     authDomain: "asp-work-share.firebaseapp.com",
     projectId: "asp-work-share",
     storageBucket: "asp-work-share.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abcdef"
   };
   ```

## 2단계. 로그인 계정 만들기 (Firebase Authentication)

이 앱은 지수·다경 두 분만 로그인해서 쓸 수 있도록 이메일/비밀번호 로그인 화면이 있습니다.

1. Firebase 콘솔 왼쪽 메뉴 → **빌드 → Authentication** → **"시작하기"**
2. **Sign-in method** 탭 → **이메일/비밀번호** 선택 → 사용 설정 → 저장
3. **Users** 탭 → **"사용자 추가"** 클릭
4. 지수님 이메일 + 비밀번호 입력 → 추가
5. 같은 방법으로 다경 선생님 계정도 하나 더 추가 (총 2개 계정)

> 실제로 쓰시는 이메일 주소일 필요는 없어요 (예: `jisu@asp-work-share.local` 처럼 형식만 이메일이면 됩니다). 다만 비밀번호는 두 분이 각자 잘 기억할 수 있는 걸로 정해주세요.

## 3단계. 앱에 Firebase 설정 붙여넣기

이 폴더의 **`firebase-config.js`** 파일을 열어서, 위에서 복사한 값을 아래 형태로 그대로 채워 넣고 저장하세요.

```js
window.FIREBASE_CONFIG = {
  apiKey: "AIza...",
  authDomain: "asp-work-share.firebaseapp.com",
  projectId: "asp-work-share",
  storageBucket: "asp-work-share.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abcdef"
};
```

> 이 값들은 비밀번호가 아니라 "이 웹앱이 어느 Firebase 프로젝트를 쓰는지" 알려주는 공개 설정값이라 코드에 그대로 넣어도 괜찮습니다.
> 실제 접근 제어는 2단계에서 만든 로그인 계정 + 아래 5단계의 Firestore 규칙이 담당합니다.

## 4단계. GitHub에 올리고 GitHub Pages로 배포하기

1. https://github.com 접속 → 로그인 → 오른쪽 위 **+ → New repository**
2. 저장소 이름 입력 (예: `asp-work-share`) → **Public**으로 설정 → Create repository
   > GitHub 무료 요금제는 **Private 저장소에서 Pages를 지원하지 않습니다.** Public으로 만들어야 배포 화면(Settings → Pages)에서 Branch를 선택할 수 있어요.
   > 저장소가 공개되면 코드와 Firebase 설정값도 누구나 볼 수 있지만, 로그인 계정을 모르면 로그인 화면을 통과할 수 없고, 아래 5단계 규칙으로 Firestore 자체도 로그인 없이는 막혀 있어서 안전합니다.
3. 방금 만든 저장소 페이지에서 **"uploading an existing file"** 링크 클릭
4. 이 폴더 안의 5개 파일을 전부 끌어다 놓기: `index.html`, `style.css`, `app.js`, `firebase-config.js`, `README.md`
5. 아래 **Commit changes** 클릭
6. 저장소 상단 메뉴 **Settings → Pages**
7. **Branch**를 `main` (또는 `master`) / 폴더는 `/ (root)` 선택 → **Save**
8. 1~2분 후 같은 화면에 나오는 주소 (`https://아이디.github.io/asp-work-share/`)로 접속하면 로그인 화면이 뜹니다.
   이 주소를 다경 선생님께 공유해주세요.

> 이미 저장소를 Private으로 만드셨다면: Settings → General → 맨 아래 "Danger Zone" → "Change visibility" → Public으로 변경하시면 됩니다.

## 5단계. Firestore 보안 규칙 설정 (중요 — 로그인한 사람만 접근 허용)

Firebase 콘솔 → Firestore Database → **규칙** 탭에서 아래처럼 바꿔주세요. "테스트 모드"(누구나 읽기/쓰기 가능)를 로그인한 사용자만 가능하도록 좁히는 규칙입니다:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

`request.auth != null`은 "2단계에서 만든 계정으로 로그인한 사람만" 이라는 뜻이에요. 저장소가 Public이어도 이 규칙 덕분에
로그인하지 않은 사람은 Firestore 데이터에 접근할 수 없습니다.

## 6단계. (선택) 실제 파일 업로드를 쓰려면 — Firebase Storage 설정

업무매뉴얼 · 소통일지의 "📤 파일 업로드" 버튼으로 파일 자체를 첨부하려면 Firebase Storage가 필요해요. 다만 2025년 10월부터 정책이 바뀌어서, Storage는 **무료 요금제(Spark)에서는 쓸 수 없고 유료 요금제(Blaze)로 전환해야만 사용할 수 있습니다.** 사용량이 적으면(무료 할당량 5GB 저장 / 하루 1GB 다운로드 이내) 실제 청구 금액은 0원이지만, 신용/체크카드 등록은 필요해요.

1. Firebase 콘솔 왼쪽 아래 **"업그레이드"** (또는 ⚙️ → 사용량 및 결제) → **Blaze 요금제 선택** → 결제 계정(카드) 연결
2. 왼쪽 메뉴 → **빌드 → Storage** → **"시작하기"** → 위치는 Firestore와 동일하게 `asia-northeast3` 권장 → 완료
3. Storage → **규칙** 탭에서 아래처럼 바꿔주세요 (Firestore 규칙과 동일한 의미: 로그인한 사람만 업로드/다운로드 가능):
   ```
   rules_version = '2';
   service firebase.storage {
     match /b/{bucket}/o {
       match /{allPaths=**} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```
4. 저장 후 앱을 새로고침하면 업무 리스트/회의/아이디어/소통일지/업무매뉴얼/자료실의 "📤 파일 업로드" 버튼으로 실제 파일(사진, PDF, 한글 파일 등)을 올릴 수 있어요. (설정 전에는 눌러도 안내 메시지만 뜹니다.)

> 카드 등록이 부담스러우시면 이 단계는 건너뛰셔도 되지만, 현재 버전은 링크 직접 등록 기능이 빠지고 업로드 전용으로 바뀌어서 이 단계를 완료해야 파일 첨부 기능을 쓸 수 있어요.

## 7단계. 사용하기

1. 배포된 URL로 접속하면 로그인 화면이 먼저 뜹니다 — 2단계에서 만든 이메일/비밀번호로 로그인
2. 상단 오른쪽에서 본인 이름(지수 / 다경) 선택 — 브라우저에 기억되어 다음에는 다시 선택할 필요 없어요 (게시글 작성자 표시용이며, 로그인 계정과는 별개예요)
3. 각 탭의 "+ 추가" 버튼을 누르면 **팝업 없이** 바로 새 줄/카드가 생기고, 그 자리에서 바로 타이핑하면 됩니다 (Notion처럼 자동 저장, 별도의 "저장" 버튼 없음)
4. 오른쪽 위 "로그아웃" 버튼으로 로그아웃할 수 있어요

**좌측 사이드바** (모든 탭에서 항상 보여요)

- 미니 캘린더 — 날짜를 클릭하면 캘린더 탭으로 이동해서 그날 일정을 볼 수 있어요.
- 📌 중요 일정 D-day — 캘린더 탭과 같은 목록을 사이드바에서 바로 확인/추가할 수 있어요.
- 📝 메모 — 어느 게시판에도 안 맞는 잡다한 메모를 입력 후 Enter로 바로 등록. 체크하면 완료 표시, 다시 누르면 취소돼요.

**탭 구성**

- **📢 공지사항**: 게시판 형식 — 제목 목록만 보이고, 클릭하면 내용을 볼 수 있어요.
- **📅 캘린더**: 다른 모든 게시판(업무 리스트, 개별 업무리스트, 회의, 아이디어, 공지사항, 소통일지, 자료실)에 날짜가 입력된 항목을 자동으로 모아서 달력에 표시합니다.
  - 담당자가 1명뿐인 업무/개별 업무리스트 항목은 "개인 일정"(지수/다경 색상), 그 외는 "공동 일정"(파란색)으로 자동 구분됩니다. 상단 필터로 전체/공동/개인만 골라볼 수 있어요.
  - 날짜를 클릭하면 그날의 일정 목록이 아래 뜨고, 각 항목을 클릭하면 해당 게시판 탭으로 바로 이동합니다.
- **📋 업무 리스트**: 상단의 **전체 / 교육 / 행정 / 시스템 / 중재 탭**을 눌러 분류별로(또는 전체를 한번에) 봅니다. 각 업무명 앞에는 소분류(일간/주간/분기/반기/연간 등) 배지가 색깔로 붙어서 한눈에 주기를 알 수 있어요. 마감일은 있을 때만 눌러서 열 수 있어요("+ 마감일"). 열 제목(날짜/담당자/진행도)을 클릭하면 정렬됩니다. 비고 칸(📝)은 업무 진행 상황을 기록하는 로그예요 — 등록한 기록은 나중에 수정·삭제도 할 수 있어요. 첨부 칸(📎)은 파일 첨부고, 긴 파일명은 잘려서 표시되니 전체 이름은 마우스를 올려 확인하세요. 툴바의 **"완료 항목 숨기기"** 체크박스를 켜면 진행도가 "완료"인 업무는 목록에서 안 보여요. **"✅ 정기업무 현황"** 버튼을 누르면 그 안에서 바로 정기업무 체크리스트를 펼쳐볼 수 있어요 (매일/주간/매달/분기별/반기별/연간, 기간이 바뀌면 자동으로 "대기"로 리셋).
- **🙋 개별 업무리스트**: 상단에서 **지수 / 다경 탭(엑셀 시트처럼)**을 눌러 각자의 표로 전환합니다. 분류는 회의/교육/TDM/기타 중 고르거나, "+ 직접 추가..."로 새 분류를 그때그때 만들 수 있어요. 마감일도 있을 때만 눌러서 열 수 있어요.
- **🗓 회의**: 상단의 **주간회의 / 월간회의 / ASP 팀회의 탭**으로 나뉘고, 게시판처럼 제목 목록만 보이다가 클릭하면 상세 내용을 볼 수 있어요. **매주 금요일 오후 4시 주간회의는 자동으로 만들어져요** (둘 중 누구든 그 주에 한 번 앱을 열면 자동 생성됩니다). 참석자는 지수·다경 두 분으로 고정 표시되고, 상세 화면에서 회의 자료 파일을 첨부할 수 있어요.
- **💡 아이디어**: 자유롭게 아이디어 제안 (검토중/채택/보류 상태 지정), 파일도 첨부할 수 있어요.
- **💬 소통일지**: 날짜·분류(간호팀/전산팀/질병청/ASP사무국/인재경영팀/약제팀/기타 중 선택)·업무·대상·소통내역·수신/발신·전화번호·참여한 사람·비고·첨부 파일. "분류"와 "업무" 열 제목을 클릭하면 그 기준으로 정렬돼요.
- **📔 업무매뉴얼**: 상단의 **중재/TDM/행정/교육/시스템/개인 공부/기타 분류 탭**으로 나뉘고, 그 안에서 게시판처럼 제목 목록 → 클릭하면 상세 화면으로 들어가서 내용을 정리할 수 있어요. 항목마다 파일을 여러 개 첨부할 수 있어요.
- **🗂 자료실**: 상단의 **프로그램/양식/매뉴얼/공부자료/가이드라인/기타 분류 탭**으로 나뉘고, 업무매뉴얼처럼 게시판 형식(목록 → 클릭 → 상세)으로 자료명과 파일을 관리합니다. 링크 등록은 없고 **파일을 직접 업로드**하는 방식이에요 (6단계의 Firebase Storage 설정이 필요해요).

두 분이 각자 다른 컴퓨터에서 동시에 접속해 있어도, 한쪽에서 추가·수정한 내용이 실시간으로 반대편 화면에도 반영됩니다.
(다만 같은 칸을 정확히 동시에 타이핑하는 경우는 마지막에 입력을 끝낸 쪽 내용이 저장됩니다 — 실시간 공동 편집기 수준의 충돌 해결은 아니에요.)
